# Proposal

## Why

A sync resolves a conflict of git in a copy by words, also in a generated file (a lock file, a file its attributes
mark `linguist-generated` or `-diff`, one with a "Generated by" header): `WordScope::AllTexts` of
[develar/branch-deck#232](https://github.com/develar/branch-deck/issues/232). Since #229 an update leaves such a file a
conflict, but the copies of a sync still merge its text. A merge of words can keep a line the other side renamed or
dropped: the copy is clean as text, its build fails or the file is stale against its inputs, while the user's tree,
which has the commit the copy lacks, builds. Nothing said so.

To leave such a file a conflict of the sync would turn the common case, two branches that each add a dependency to one
lock file, into a conflict on every sync. So the copy still resolves, and says so (option 2 of #232).

## What Changes

- `resolve_by_words` resolves a generated file in a sync as before and names why it is generated
  (`ResolvedFile::generated_by`), from the `check-attr` it runs anyway, which now always reads the attributes of a
  generated file: no process more. An update refuses a file its attributes mark before it reads a blob.
- `WordResolutionSummary.generated` lists them; the resolve line of the mapping note carries them as a JSON tail after
  its counts (`v-commit-resolved-v1:<version> <conflicts> <files>[ <json>]`), which an older reader ignores and a tail
  that doesn't parse turns into an older resolve. `RESOLVE_VERSION` 5, so a copy of resolve 4 is checked once and its
  note written again; `CONFLICT_CHAIN_VERSION` 4 and `STACK_BUILD_VERSION` 4, whose records keep the lists as JSON.
- After its builds a sync tells, once, of each virtual branch (with the copies of the branches it is built on) and of
  each stack branch, the generated files the words merged that its tip still holds, each with the commit the copy
  lacks (`sync_core::regenerate`, `SyncReport.regenerate`): no process without such a merge, one `log` when one is
  held, one `cat-file --batch-check` more when one lies below its tip.
- `brd sync` prints `regenerate` and `regenerate_fix` of a branch and `generated` of each resolved commit; `brd status`
  `generated` of `resolved_by_words`; the Resolved by Words view marks a generated file.

What the row, the push and the start do with it is the change `232-regenerate-asks-first`; the refusals of `brd` are
`232-regenerate-refusals-of-brd`.

Capabilities: `cli/agent-cli`, `repository/update-project`, `commit/commit-row`.
