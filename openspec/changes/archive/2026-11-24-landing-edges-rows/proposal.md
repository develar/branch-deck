# Proposal

## Why

With the edges of `landing-edges`, a row says one need in one sentence, and a start whose every need is landing in a
running Safe Push is a wait, not the user's step: on idea-1 the fifteen "Needs acp-load-replay" of the stack of
`air-home-watch` become one quiet "Lands after acp-load-replay". The popover of such a start no longer offers the
start that fails as its default, and its long paths stay inside it.

## What Changes

- `StepKind::AfterLanding { needed, robot, edges, restart }`: row 1′ while every edge of the needs waits, a wait
  (`is_wait`); the Status cell "Lands after acp-load-replay" ("Restart after acp-load-replay" before its own failed
  robot), the slot empty, the node `Waiting`; `brd status` `after_landing` with `lands_after`.
- `StepKind::NeedsBranch` carries the edges: the row names the first, its hover one sentence ("Uses 5 names of
  acp-load-replay in acp_load_replay.rs (Effect, Input +3)"), its click the fix of the edge: the restack, "Restart
  acp-load-replay", "Group 1a2b3c4d into claude-folds", "Safe Push Whole Stack". "brd check lists them" is gone.
- The Safe Push popover: the refusal as a one-line headline and a wrapped detail, its fix focused and Start Anyway
  `outline`; while every edge waits Start Anyway is in the "⋯" of the footer. A long path wraps inside it.
- The toast of a merge: the start of the subject that waited for the robot ("Start flow") once its Update Project
  landed it, in place; nothing starts by itself.

Capabilities: `branch/landing-plan`, `branch/next-step`, `branch/patronus`, `repository/landed-commits`.
